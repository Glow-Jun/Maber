# Maber 设计文档

日期：2026-11-07
状态：已与需求方逐节确认
目标版本：v0.1.0（首个里程碑）

## 1. 产品定位

Maber 是一个类 Typora 的轻量级 Markdown 阅读器，以阅读为核心体验，保留必要的编辑能力。

- 界面极简，像一张白纸，专注于呈现内容
- 支持完整 Markdown 渲染、LaTeX 公式、Obsidian 方言语法
- 渲染模式与源码模式可切换
- 轻量化，但不牺牲大文件打开能力
- 文件以非独占方式打开，其他程序可同时编辑同一文件

### 1.1 竞品结论（2026-11 调研）

| 产品 | 结论 |
|------|------|
| Typora | 渲染质量标杆（本质为 web 渲染），闭源收费，重编辑，无 Obsidian 语法 |
| Mark Text | 开源类 Typora，Electron 臃肿，基本停止维护 |
| Zettlr / Obsidian | 功能强但界面复杂、重编辑器 |
| READU.md | 定位接近，但为分栏式编辑预览，闭源 |
| WinUI.Markdown（NuGet） | 证明 WinUI 3 原生渲染路线可行，但 0.x 阶段，效果距 Typora 明显 |

空档：**纯阅读优先 + 极简界面 + Obsidian 语法 + 原生轻量（非 Electron）** 的组合目前无成熟开源产品，Maber 定位成立。

### 1.2 双形态

两种形态共用同一渲染内核，区别只是壳的配置：

- **Slim Mode（轻化模式，主形态）**：双击 md 文件打开时进入。无侧栏、无菜单栏，纯净单文件阅读体验。大纲用 Ctrl+K 悬浮唤出、失焦自动收起；常用操作（切源码、保存）在右键菜单与快捷键中；顶部一条极细悬浮信息条（文件名 + 模式指示），鼠标移开自动淡出。
- **Total Mode（完整模式）**：直接启动 Maber 时进入。包含 Slim 全部能力，外加左侧可折叠边栏（大纲、最近文件）、语法速查、LaTeX 公式辅助器、完整设置。

## 2. 总体架构（已选定方案 A）

**WinUI 3 壳 + WebView2 内容区。** WinUI 3 只负责窗口、标题栏、文件服务与面板；阅读/编辑区整体为 WebView2，内用 markdown-it + KaTeX + mermaid 渲染、CodeMirror 6 做源码编辑。

选定理由：Typora 的渲染质量本质上来自 web 渲染；WebView2 是 Win10/11 系统组件，不捆绑浏览器内核，安装包小；Obsidian 语法有现成开源插件生态。原生渲染（方案 B）与混合管线（方案 C）因公式/图表生态缺失或风格不一致被否决。

窗口形态：当前为单窗口单文件；架构上保留单窗口多标签的演进通道（后续可在设置中切换）。

## 3. 模块划分

```text
Maber/
├─ src/
│  ├─ Maber.App      # WinUI 3 壳（.NET 10）：窗口、标题栏、模式切换、文件关联
│  ├─ Maber.Core     # 文件服务、外部修改监视、编码检测、设置、文档状态（无 UI 依赖，可单测）
│  └─ Maber.Web      # 渲染前端（TS/JS）：构建产物嵌入 App，作为 WebView2 静态资源
├─ docs/             # 设计文档、决策记录
└─ tests/            # Core 单元测试 + 渲染内核快照测试
```

职责边界：App 管壳，Core 管文件，Web 管呈现。壳与渲染内核通过一套 JSON 消息协议通信（`loadDocument` / `setMode` / `themeChanged` / `outlineRequest` / `checkboxToggle` / `contentChanged` 等），协议稳定后两侧可独立演进。

## 4. 渲染内核

### 4.1 语法支持清单

基础（必做）：CommonMark + GFM（表格、任务列表、删除线、自动链接）、代码高亮。

Obsidian 核心集 + Mermaid：

| 语法 | 处理 |
|------|------|
| `$...$` / `$$...$$` | KaTeX 渲染，解析失败降级为红字原文 |
| `> [!note]` 系列（含折叠 `-`） | Callout 渲染 |
| `==高亮==` | `<mark>` |
| `[[wikilinks]]`（含 `#标题`、`|别名`） | v0.1 渲染为链接样式；跨文件跳转能力随 Total Mode 演进 |
| `![[图片嵌入]]` | 解析为图片 |
| `#标签` | 标签样式渲染 |
| `%%注释%%` | 阅读模式隐藏 |
| YAML frontmatter | 解析显示为属性区，不混入正文 |
| `[^脚注]` | 脚注渲染 |
| ``` ```mermaid ``` | Mermaid 懒加载渲染，语法错误块级提示不影响其余内容 |

### 4.2 性能策略

- Mermaid 按需懒加载：文档无图表则零开销
- 大文件按标题分块增量渲染：先出首屏，避免长文档一次性阻塞
- 源码模式 CodeMirror 6（轻于 Monaco 数量级），带 md 语法与公式高亮；`Ctrl+E` 与渲染模式互切，切换保持视口位置

## 5. 文件处理（非独占）

- `FileShare.ReadWrite` 打开，Obsidian、编辑器、同步盘等可随时写同一文件
- `FileSystemWatcher`（配轮询兜底）监视外部修改：
  - 本地无未保存改动 → 静默热重载，保持阅读位置
  - 有未保存改动 → 行内提示，由用户选择保留哪边，绝不静默覆盖
- 保存：写临时文件 + 原子替换（`File.Replace`），降低损坏风险
- 编码：UTF-8 优先，BOM 检测，GBK 回退

## 6. 编辑能力（保留但克制）

- 渲染模式中点击任务复选框，直接写回源文件
- `Ctrl+S` 保存、`Ctrl+E` 模式切换、`Ctrl+F` 页内查找（结果高亮）、`Ctrl+K` 大纲
- 不做工具栏、不做所见即所得混排编辑——编辑入口即源码模式

## 7. 错误处理

| 场景 | 行为 |
|------|------|
| 文件被外部删除 | 页内行内提示，不崩溃；有本地编辑时引导另存 |
| mermaid 语法错误 | 块级错误提示，不影响其余内容 |
| KaTeX 解析失败 | 降级为红字原文 |
| 二进制/乱码文件 | 打开前检测，行内提示拒绝渲染 |
| 保存冲突 | 以用户选择为准，不静默覆盖 |

任何错误路径不允许崩溃、不允许丢内容。
